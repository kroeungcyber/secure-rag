# NGO Pilot — Plan (step by step)

Date: 2026-08-19
Status: Approved (defaults) — awaiting user inputs for decisions 1–4 (companion to the pilot spec)

## Phase 0 — Pre-flight
1. Pick the NGO / office / team (decision 1).
2. Inventory the hardware → choose the model (decision 2).
3. List the corpus documents; get data-protection review (decision 3).
4. Recruit pilot users and assign roles (decision 4).

## Phase 1 — Setup
5. Install Ollama; `ollama pull llama3.2:3b nomic-embed-text` (or `gemma4` +
   `nomic-embed-text` if hardware allows).
6. `pip install -e .`; set `PROGRAM.md` (commands OFF, path whitelist to the
   corpus dir, URL whitelist, `redact_pii: true`).
7. `srag add <corpus-dir>`; sanity-check retrieval on a few known questions.

## Phase 2 — Onboard
8. Admin creates invites per user (role + document access).
9. Each user claims their account and walks the onboarding checklist.
10. Baseline measurement: time-to-answer for a handful of "known" questions
    *without* the tool.

## Phase 3 — Run (2–4 weeks)
11. Users ask real questions; audit log accumulates.
12. Weekly: skim `audit.jsonl`, note failures/hallucinations, clear stuck users.

## Phase 4 — Review
13. Re-measure time-to-answer (compare to baseline).
14. Citation-accuracy spot-check: sample N answers, verify each source actually
    supports the answer (flag the model-capability gap if `llama3.2:3b`).
15. Survey: usefulness rating + "keep using it?".

## Phase 5 — Decide
16. Apply the go/no-go threshold (decision 8).
17. Write the one-page pilot report (metrics + verdict + what broke).
18. Fold the report into the portfolio + admissions project case.
